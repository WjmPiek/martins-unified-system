PROPOSED NATIVE DESIGN

Use existing franchise identity and permissions throughout. Keep territorial
planning records distinct from recorded monthly transactions within the same
database, so forecasting cannot change actual sales, royalties or performance.
Add versioned boundaries, evidence, assumptions and calculation snapshots.
Reuse the existing background queue for bounded, retryable research work.

Use Unified's agreement method, brackets, fallback scale rules and minimum
royalties. Compass's flat default 6% is not a replacement for those contracts.
Preserve source fee bands as commercial ceilings, then apply financial limits.
Do not adopt Unified's stored 1.6% target-growth default as a universal forecast.

STAGE 1 — IMPLEMENTED LOCALLY

1. Native Territory & Valuation entry within Franchise Details.
2. Two additive tables: franchise_territories and territory_valuation_snapshots.
   Existing records and role assignments are unchanged by the migration.
3. Immutable application-level calculation history: each save appends a
   revision, including inputs, evidence, results, formula version and the
   agreement/royalty settings used. There is no history-edit/delete endpoint.
4. Existing view/edit/export permission checks plus franchise ownership checks.
   Financial editing is restricted to Admin/Super Admin/Finance Manager with
   the applicable existing edit permission. No new permissions are granted.
5. CSRF protection for new write endpoints, optimistic version checks, bounded
   request sizes and validation of numerical values and GeoJSON topology.
6. GeoJSON polygon import and road-map overlay using the existing Google Maps
   configuration. Polygon holes and multipolygons are supported. Automatic
   boundary discovery and interactive boundary editing are not in stage 1.
7. Evidence records with metric, source link, observation/data date, retrieval
   date, confidence, method and value; source links are displayed safely.
8. The original seven-factor scorecard and five commercial fee bands.
9. Sixty monthly forecast rows with annual summaries, operating costs, service
   mix, policy cash contribution, existing royalty rules, salary, cash reserves,
   tax planning allowance, finance/capex/working adjustments and repayments.
10. Upfront or instalment funding, optional interest, exact final instalment,
    cash shortfalls, investment recovery and a 20% sales-downside scenario.
11. Provisional pricing is capped at the score band and searched against actual
    monthly expected/downside cash flow, target margins and a downside buffer.
    Missing documented scores, unconfirmed assumptions, missing royalty setup,
    or incomplete sourced boundary/evidence prevent a recommended price.
12. Saved-revision JSON export. Saved results are visible to authorised viewers.

RESEARCH SOURCE FINDINGS

Stats SA provides ward-level Small Area Population Estimates, 2022, using
2020 ward boundaries. A custom franchise polygon is a separate geography;
allocation from wards must remain a modelled estimate with a stated method.
https://www.statssa.gov.za/?p=18967
https://www.statssa.gov.za/wp-content/uploads/2025/11/Ward-statistical-product-technical-note.pdf

SARS publishes aggregate annual tax statistics. Taxpayer averages are not
household incomes, and municipal boundaries/data periods must be recorded.
https://www.sars.gov.za/about/sars-tax-and-customs-system/tax-statistics/
https://www.sars.gov.za/wp-content/uploads/2025taxstats/2025-Tax-Statistics-PDF-.pdf

Stats SA mortality is the source for the demand proxy, which must be matched
to a same-period population denominator. It is not a count of funerals in a
custom franchise boundary.
https://isibaloweb.statssa.gov.za/pages/surveys/pss/hvs/cod/2024/cod2024.php

CIPC registration status can support business identity verification; an entity
registration alone does not establish that a particular branch is operating.
https://www.cipc.co.za/wp-content/uploads/2025/08/Customer-Notice-36-of-2025-Deregistration-Complaints.pdf

LOCAL REVIEW INSTRUCTIONS

The supplied patch applies at the inspected base commit and includes new files.
It is not a deployment script. Build/review in an isolated copy only.

Install the existing requirements plus the added shapely==2.1.2 dependency.
After verifying the target database is disposable staging, review and run the
additive migration. Enable TERRITORY_VALUATION_ENABLED=true only in that isolated
environment. The default remains false.

The migration revision is v128_native_territory after v127_insurance_app.
Disable the flag to hide the new routes/page. Preserve the new tables/history
when disabling; a downgrade removes planning history and needs a backup decision.

Repeatable local test invocation:
  python -m pytest --noconftest --confcutdir=tests -p no:cacheprovider tests -q
The cache plugin is disabled because pytest discovers an unrelated parent
configuration outside this workspace and attempts to write its cache there.
